自主决策通用防御智能体
架构设计方案

基于 PentAGI 架构分析的建设思路 | 2026-05-09

目标：构建面向多变真实网络环境的自主决策通用智能体，作为网络安全从业人员的智能增强伙伴，实现从威胁感知、分析研判到响应处置的全闭环自主操作，推动网络安全防御体系从自动化到智能化的根本性跃升。

一、PentAGI 的启示与差距

1.1 可复用模式

机制PentAGI 实现借鉴价值
多 Agent 分层协作Researcher → Developer → Executor 三阶段流水线感知→分析→执行的认知分层可复用
四层监督机制Adviser/Planner/Limits/Reflector多层决策质量控制的工程范式，小模型场景提升 2x
ChainAST 消息压缩结构化分段摘要 + QA 保留 + 尾部保留长对话上下文管理的可靠方案
三类记忆联动长期(向量)/工作(上下文)/情景(历史)记忆闭环知识积累与经验复用的核心基础设施
沙箱隔离执行Docker + 独立网络 + 双节点部署安全操作的基础保障

1.2 关键差距

  • PentAGI 是攻击视角，缺少防御场景的认知框架与知识体系
  • 决策不具备可解释性——没有审计链路，无法追溯每个决策的证据依据
  • 单一渗透场景，不支持应急响应、逆向分析、漏洞挖掘等多场景动态切换
  • 缺乏对抗鲁棒性——没有对抗干扰防护、操作门禁、熔断机制
  • 线性 Flow 模型，无法支持并行子任务和动态重规划

架构核心思想

  • 分层认知：任务理解 → 编排决策 → 感知/分析/执行，每层各司其职
  • 双闭环：内闭环（实时决策治理）保证每次决策可靠；外闭环（事后经验进化）保证系统持续成长
  • DAG 编排：替代 PentAGI 的线性 Flow，支持并行子任务和失败时的局部重规划
  • 场景感知：路由到不同场景知识库，加载对应的工具集、Playbook 和历史案例

三、核心模块详细设计

3.1 任务理解层

这是 PentAGI 最薄弱的一环，也是防御体系最关键的部分——防御任务往往来自告警、工单、报告等多种非结构化输入。

能力实现方案
多格式输入解析独立 Parser Pipeline：自然语言 → Markdown/PDF → 压缩包 → API 接口文档，统一输出结构化 Task Graph
意图识别LLM + Few-shot 将用户输入映射到场景标签（渗透测试/应急响应/漏洞挖掘/逆向分析/合规检查），并识别关键约束（时间窗口、影响范围、优先级）
实体抽取提取 IP、域名、CVE 编号、工具名、文件路径、时间约束、资产标识等，形成结构化 Context Object
任务规划借鉴 PentAGI Planner Agent，增加场景模板库作为先验约束，避免 LLM 自由发挥导致偏离场景

3.2 场景路由与编排引擎

PentAGI 只有单一渗透流程。防御体系需要多场景动态路由。

输入任务 → 场景识别 → 加载场景知识库 → 生成 SubTask DAG

        模板库       模板库        模板库        模板库       模板库

机制设计
DAG 而非线性 Flow允许并行子任务——例如同时进行信息收集和漏洞库查询；子任务间用依赖关系连接
动态重规划当某个子任务失败或发现新信息（如扫描发现意外端口），Planner 自动重新规划下游 DAG
场景知识库每个场景独立维护 Tool Profile（可用工具及参数约束）、Playbook（标准操作流程）、历史案例（向量化）
优先级调度应急响应场景下，信息收集和阻断类 Action 自动获得更高优先级

3.3 Agent 角色体系

在 PentAGI 的 11 种 Agent 基础上，针对防御场景扩展：

AgentPentAGI 原有防御体系新增/强化职责调用上限
Perceiver（感知）无态势感知：日志采集、流量分析、资产发现、告警聚合100
Analyst（分析）无研判推理：告警关联分析、攻击链还原（ATT&CK映射）、根因定位、影响评估100
Responder（处置）无响应执行：流量阻断、主机隔离、补丁修复、服务恢复100
Researcher（研究）有扩展：支持防御侧威胁情报查询、CVE 漏洞库比对、IOC 关联20
Developer（规划）有强化：场景感知的多策略规划，生成带有置信度评分的候选方案20
Executor（执行）有保持：工具调用与结果处理，增加操作前后的状态校验100
Adviser（监督）有(Beta)强化：增加安全边界守卫（禁止操作白名单外命令）、风险阈值拦截、异常行为检测20
Reflector（反思）有保持：LLM 调用失败时的反思纠错20
Auditor（审计）无核心新增：记录每个决策的证据链、生成可审计的决策日志、关键操作门禁确认20
Memorist（记忆）有保持：向量存储写入/检索，增加防御经验模式存储20
Operator（运维）无核心新增：系统健康巡检、配置合规检查、补丁与版本管理、备份恢复、资源容量规划、服务启停与编排、日志轮转与清理、证书与密钥生命周期管理100

3.4 运维 Agent 详细设计（Operator）

运维 Agent 是防御体系的基础保障层，负责系统的日常健康维护与配置管控。不同于 Perceiver/Analyst/Responder 面向安全事件，Operator 面向系统本身的可靠性和合规性。

子能力功能描述典型工具/操作
健康巡检定期检查系统、服务、进程运行状态，自动识别异常并生成巡检报告systemctl status, kubectl get pods, docker ps, curl health endpoint, top/htop
配置合规检查对照安全基线（CIS/NIST/等保）自动审计系统配置，标记不合规项lynis, openscap, cis-benchmark rules, 自定义合规脚本
补丁与版本管理扫描可用更新，评估风险等级，生成升级计划，执行灰度升级apt/yum update check, CVE-version mapping, canary deploy, rollback
备份与恢复自动化数据备份策略管理，定期校验备份完整性，灾难恢复演练pg_dump, restic, velero, snapshot, S3 sync
资源容量规划监控 CPU/内存/磁盘/网络使用趋势，预测瓶颈并提前扩容建议Prometheus metrics, df -h, iostat, capacity forecast model
服务启停与编排按依赖顺序安全启停服务，处理滚动更新和零停机部署docker compose, kubectl, systemctl, ansible playbook
日志轮转与清理管理日志保留策略，自动轮转归档，清理过期数据和临时文件logrotate, journalctl --vacuum, find + rm, tmpwatch
证书与密钥管理监控 TLS 证书到期时间，自动续期或告警；密钥轮换与合规存储certbot, openssl, vault, aws secrets manager

运维 Agent 与其他 Agent 的协作关系：

  • → Perceiver：接收巡检发现的异常指标，触发感知 Agent 进行深度态势分析
  • → Responder：当发现配置漏洞或过期组件时，将修复任务转交处置 Agent 执行
  • → Auditor：巡检结果和配置变更记录同步到审计链，确保运维操作可追溯
  • → Memorist：将系统健康基线和最佳配置模式存入长期记忆，用于异常检测基准

4.2 实现机制

层级机制说明
LLM 输出层强制 Rationale 输出System Prompt 要求每个 Action 必须包含 rationale 字段，说明决策依据和推理过程
工具执行层自动证据关联工具执行输出（终端日志、API 响应）自动关联到对应决策记录，形成完整证据链
操作门禁层分级管控高风险操作（阻断流量、删除数据、修改配置）必须经 Auditor Agent 确认；可配置人工审批阈值
存储层审计日志持久化所有决策记录存入 PostgreSQL + Neo4j 图中，支持按任务/时间/Agent 多维追溯
展示层决策链路可视化前端以时间线+证据节点图形式展示，用户可点击每个决策查看完整的推理链和引用证据

4.3 安全操作分级

风险等级操作示例管控措施
低（只读）查询日志、扫描端口、检索 CVE自动执行，无需审批
中（影响小）创建隔离 VLAN、修改非生产防火墙规则Auditor 自动审批 + 事后审计
高（影响大）阻断生产流量、隔离核心服务器、删除文件Auditor 审查 + 人工确认（可配置自动审批阈值）
危险（不可逆）DROP 数据库表、卸载安全组件、修改系统内核参数强制人工审批，不允许自动执行

五、运行鲁棒性设计

机制设计解决的问题
对抗干扰防护Agent 输入加入完整性校验层：检测 Prompt Injection 尝试、异常指令模式、结构化字段篡改防止攻击者通过污染日志或告警来误导 Agent
状态快照与回滚每个 Task 完成时自动保存状态快照（DAG 进度 + 工具输出 + Agent 状态），失败时回滚到最近检查点长任务中断后不需要从头开始
熔断机制Adviser 检测到连续异常决策（3次高风险操作或5次工具调用失败），自动暂停并请求人工介入防止 Agent 在异常状态下持续产生错误决策
确定性保证关键推理链路使用 Temperature=0 + 固定 seed，确保相同上下文产生相同输出满足审计可复现性要求
行为复现完整的 Action Log + Message Chain 序列化，支持逐步骤回放，所有状态可复原事后复盘和合规审计
工具调用去重借鉴 PentAGI 重复检测器，防止 Agent 陷入无效循环避免资源浪费和超时

总结：本方案的核心思路是在 PentAGI 验证过的多 Agent 协作 + 多层监督工程范式基础上，针对防御场景做四个关键突破：

  1. 决策可解释性与审计体系——每个决策携带完整的 rationale + evidence 链路
  2. 多场景认知框架——从单渗透扩展为场景感知的动态路由 DAG 编排，覆盖渗透/应急/挖洞/逆向/运维/合规
  3. 运行鲁棒性体系——从简单的重试+反思，升级为对抗防护+检查点+熔断+确定性保证的完整韧性框架
  4. 运维保障层——Operator Agent 提供系统健康巡检、配置合规、补丁管理、备份恢复的自主运维能力，确保防御体系自身的高可用性
